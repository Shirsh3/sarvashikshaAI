2. How we tested

Backend (API)

  • Tooling: Python HTTPS clients against staging API (be_rigorous.py, ad-hoc payment/order scripts).
  • Auth: Ops POST /auth/admin-login; foodie/chef via captcha → OTP → verify (using staging responses).
  • Data setup: Created profiles on society CRESCENT PARC, free units; chef menu-catalogue; meal publish (when FSSAI allowed) or reused existing meals.
  • Assertions: HTTP status, JSON shape, authZ (401/403), bill math (item + fee + GST = total), order status transitions, rate limits, missing captcha rejection.
  • Traffic identity: Browser-like User-Agent + Origin: staging-app.putaaka.com (custom UA was Cloudflare-banned earlier).
  • Not used: Exploit tooling / attack playbooks — defensive readiness only.

Frontend (UI)

  • Tooling: Playwright Chromium headless (ui_probe.py, ui_interact.py).
  • Viewports: Desktop 1280×900 and mobile 390×844.
  • Pages: User app root login; Ops /ops login; mobile equivalents.
  • Evidence: Full-page screenshots, DOM/semantics dumps, console error capture, API traffic observed during page load.
  • Interaction: Attempted fills via DOM selectors (failed — canvas) then mouse/keyboard coordinate + Tab attempts; OTP assist via API where possible.
  • Visual review: Human review of screenshots for layout, branding, disabled CTA, captcha/T&C presence.
  • Limitation: Flutter paints UI to canvas — no reliable HTML inputs for automated click-through of cart/checkout.

Environments / timing notes

  • First pass (9 Sep evening CET): payment blocked by night window 11:00 PM – 5:00 AM (server IST).
  • Re-test (10 Sep afternoon CET / evening IST): night window clear → full payment + order lifecycle completed.
  • API redeployed mid-cycle to accounts branch; new fssai_required gate observed on meal create.

7. Recommendations — Backend

  1. Prod blocker: Never return captcha answer or OTP in API JSON. Return image/challenge only; deliver OTP via SMS. Staging may use a secure test harness, not response fields.
  2. Prod blocker: Ensure production config has dev_tools_enabled=false, disable /finance/dev/*, configure Razorpay webhooks, rotate ops credentials, enforce MFA for admin-login.
  3. Fix status_history to be append-only chronological (or sort by at before return).
  4. Document and enforce chef onboarding: FSSAI (+ GSTIN for goods/bakery) before publish; return clear error codes (already partly done).
  5. Clarify cart API contract: absolute set vs add quantity; align OpenAPI/client accordingly.
  6. Make night blackout hours configurable (env / ops setting) with staging override.
  7. Add CI API smoke: health, captcha-required, authZ negatives, cart bill integrity, payment create (mock), place order, one status transition.
  8. Complete live payment + refund + settlement E2E on staging with webhook verification.
  9. Coupon happy-path tests: create → apply → max discount cap → platform-funded flags.
  10. Clear / monitor ops pulse: stale tickets, unassigned received, pending unit assignments.

8. Recommendations — Frontend (Flutter web / apps)

  1. QA enablement: Turn on Flutter web semantics on staging (SemanticsBinding.instance.ensureSemantics()) or ship an integration_test / Patrol suite — canvas-only blocks Playwright CI.
  2. Keep captcha UI (already present); ensure refresh works, errors map from captcha_required / incorrect code, and Send OTP stays disabled until phone + captcha + T&C valid.
  3. Verify Privacy Policy / Terms of Service links open the correct pages (not tested beyond presence).
  4. Improve captcha accessibility: contrast, optional audio/alt text for the challenge.
  5. Ops login: clear wrong-password messaging, lockout countdown after 429, optional “forgot password” path if product requires it.
  6. Manual or integration_test coverage for: foodie browse → cart → checkout; chef publish wizard (catalogue → photo → windows → FSSAI prompts); ops finance/tickets modules.
  7. Surface cart quantity rules in UI (replace vs add) consistent with API.
  8. Order timeline UI must not trust unsorted status_history — sort client-side until backend fixed.
  9. Ask hosting/Cloudflare to add CSP, X-Frame-Options, HSTS on the Flutter static host.
  10. Mobile regression: re-check captcha row and long kitchen names on small widths after publish flows land.
